# Install Construct

**Construct** is an open-source, token-based design system that provides accessible, framework-agnostic UI components and design tokens for modern web applications. You'll be rendering accessible components in about two minutes — no build step required.

## What is Construct?

Construct gives you:

- **Design tokens** — a single source of truth for colors, typography, spacing, and more
- **Framework-agnostic CSS** — works with Angular, React, Svelte, Vue, or vanilla HTML
- **Accessibility first** — WCAG 2.2 AA targets, ARIA contracts, and optional tested keyboard controllers
- **Theming** — light, dark, and high-contrast modes with system-preference fallback
- **49 standalone style entries** — buttons, forms, tables, modals, metrics, status, and more

---

## Installation

```bash
npm install @neuravision/construct
```

## Integration

### 1. Import the styles

Add the foundation reset and component styles to your project's global CSS entry point:

```css
@import '@neuravision/construct/foundations.css';
@import '@neuravision/construct/components/components.css';
```

Or using a bundler's JavaScript entry point:

```js
import '@neuravision/construct/foundations.css';
import '@neuravision/construct/components/components.css';
```

For a smaller style graph, keep foundations imported once and replace the full component bundle with a standalone entry such as `@neuravision/construct/components/button.css`; the standalone entry includes its token and shared component dependencies. Foundations use only resilient local/system fallbacks and make no network request. If a product accepts the privacy and CSP tradeoff of hosted fonts, import the opt-in preset first:

```css
@import '@neuravision/construct/fonts.css';
@import '@neuravision/construct/foundations.css';
@import '@neuravision/construct/components/components.css';
```

Self-hosting guidance and the exact shipped weights are documented in `docs/fonts.md`.

### 2. Use components in HTML

All components use the `ct-` prefix with BEM-style modifiers:

```html
<!-- Button -->
<button class="ct-button" type="button">Primary</button>
<button class="ct-button ct-button--secondary" type="button">Secondary</button>
<button class="ct-button ct-button--sm" type="button">Small</button>

<!-- Form input -->
<div class="ct-field">
  <label class="ct-field__label" for="email">Email address</label>
  <input class="ct-input" type="email" id="email" />
</div>

<!-- Card -->
<div class="ct-card">
  <div class="ct-card__body">Card content here</div>
</div>
```

### 3. Apply a theme

Set `data-theme` on your root element to choose a colour scheme:

```html
<html data-theme="light">   <!-- default -->
<html data-theme="dark">
<html data-theme="high-contrast">
```

When no `data-theme` is present, Construct automatically respects the user's OS preference:
- `prefers-color-scheme: dark` → dark theme
- `prefers-contrast: more` → high-contrast theme

For a product theme, extend a built-in theme in validated JSON instead of copying generated CSS:

```bash
npx construct-theme --theme ./brand.theme.json --out-dir ./src/generated/construct
```

Load the generated `tokens.css` after every Construct stylesheet. Foundations, the full component
bundle, and standalone component entries include the built-in token sheet, so importing a product
theme earlier would let a later built-in import overwrite equal-specificity declarations:

```css
@import '@neuravision/construct/foundations.css';
@import '@neuravision/construct/components/components.css';
@import './generated/construct/tokens.css';
```

The compiler rejects unknown paths, invalid references, incomplete contracts, and failed declared contrast pairs before writing output. See the Theming page for the schema and CI options.

## Using Design Tokens

You can use Construct's CSS custom properties directly in your own styles:

```css
.my-component {
  background: var(--color-bg-surface);
  color: var(--color-text-primary);
  padding: var(--space-4) var(--space-6);
  border-radius: var(--radius-control);
  box-shadow: var(--shadow-card);
}
```

TypeScript and JSON token exports are also available for build-time tooling:

```ts
import {
  components,
  componentThemes,
  tokens,
  cssVars,
} from '@neuravision/construct/tokens';

// Resolved value
tokens.semantic.color.brand.primary; // '#16130F'

// CSS variable reference
cssVars.semantic.color.brand.primary; // 'var(--color-brand-primary)'

// Stable component decisions and their resolved dark-theme values
components.button.height;
componentThemes.dark.button.background;
```

## Optional Headless Behavior

Composite widgets can use the typed, dependency-free behavior entry:

```js
import { createModalController } from '@neuravision/construct/behaviors';

const controller = createModalController({ container, dialog, trigger });
// Call controller.destroy() when the owning view unmounts.
```

CSS styles state but cannot implement focus trapping, roving tabindex, typeahead, or focus return.

## Framework Examples

### React

```jsx
export function SaveButton({ onClick }) {
  return (
    <button className="ct-button" type="button" onClick={onClick}>
      Save changes
    </button>
  );
}
```

For controller setup and teardown in a real component lifecycle, see the published package's `examples/react/SettingsModal.jsx` example.

### Angular

```html
<!-- my-button.component.html -->
<button class="ct-button" type="button" (click)="save()">Save changes</button>
```

### Svelte

```svelte
<button class="ct-button" type="button" on:click={save}>Save changes</button>
```

### Vanilla HTML

```html
<button class="ct-button" type="button">Save changes</button>
```
