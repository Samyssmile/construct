# Theming

Construct ships three built-in colour themes — **light**, **dark**, and **high-contrast** — all controlled through a single `data-theme` HTML attribute and backed by CSS custom properties.

---

## How It Works

Primitive tokens live at `:root`. Every explicit `[data-theme]` scope emits the complete semantic and component contract, so nested light, dark, high-contrast, and product themes do not leak inherited parent values.

```css
/* Simplified excerpt from tokens.css */
:root, [data-theme="light"] {
  --color-bg-canvas: #FAFAF8;   /* warm concrete */
  --color-text-primary: #16130F; /* ink */
  --color-brand-primary: #16130F;
  --color-brand-accent: #F4581C; /* safety orange — the datum */
}

[data-theme="dark"] {
  --color-bg-canvas: #16130F;
  --color-text-primary: #FFFFFF;
  --color-brand-primary: #F1F0EB; /* light steel, so text/links stay legible */
  --color-brand-accent: #FB6E2E;
}

[data-theme="high-contrast"] {
  --color-bg-canvas: #FFFFFF;
  --color-text-primary: #16130F;
  --color-brand-primary: #16130F;
  --color-brand-accent: #B23C0C;
}
```

## Applying a Theme

### Full-page theme

Set `data-theme` on the `<html>` element to apply a theme globally:

```html
<html data-theme="light">   <!-- default -->
<html data-theme="dark">
<html data-theme="high-contrast">
```

### Scoped theme

Set `data-theme` on any container to theme only that section — useful for sidebars, headers, or embedded widgets:

```html
<body>
  <!-- Main content uses light theme -->
  <main>...</main>

  <!-- Sidebar uses dark theme regardless of root -->
  <aside data-theme="dark">...</aside>
</body>
```

### Available values

| Value | Description |
|-------|-------------|
| `light` | Light backgrounds, dark text (default) |
| `dark` | Dark backgrounds, light text |
| `high-contrast` | Maximum contrast for visual accessibility |

## System Preference Fallback

When no `data-theme` attribute is set, Construct respects the user's operating system preference automatically:

```css
/* Automatically applied when data-theme is absent */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    /* dark theme tokens */
  }
}

@media (prefers-contrast: more) {
  :root:not([data-theme]) {
    /* high-contrast theme tokens */
  }
}
```

This means **zero configuration is needed** for users who have already set their OS to dark or high-contrast mode — it just works.

## Switching Themes at Runtime

Toggle themes dynamically by updating the `data-theme` attribute:

```js
// Set a specific theme
document.documentElement.setAttribute('data-theme', 'dark');

// Follow system preference (remove explicit override)
document.documentElement.removeAttribute('data-theme');

// Persist the user's choice
function setTheme(theme) {
  if (theme === 'system') {
    document.documentElement.removeAttribute('data-theme');
    localStorage.removeItem('theme');
  } else {
    document.documentElement.setAttribute('data-theme', theme);
    localStorage.setItem('theme', theme);
  }
}

// Restore on page load (before paint to avoid flash)
const saved = localStorage.getItem('theme');
if (saved) document.documentElement.setAttribute('data-theme', saved);
```

## Validated Product Themes

A product theme extends one built-in theme and supplies only the semantic/component paths it changes:

```json
{
  "$schema": "./node_modules/@neuravision/construct/schemas/theme.schema.json",
  "name": "product",
  "extends": "light",
  "semantic": {
    "color": {
      "brand": {
        "primary": "{color.ocean.700}",
        "primaryHover": "{color.ocean.800}",
        "primaryActive": "{color.ocean.900}"
      }
    }
  },
  "components": {
    "button": { "radius": "{radius.pill}" }
  }
}
```

```bash
npx construct-theme --theme ./product.theme.json --out-dir ./src/generated/construct
```

Import the generated `tokens.css` after all Construct foundations and component entries. Those
entries include the built-in token sheet, and the product theme must come last so its
equal-specificity theme declarations win the cascade:

```css
@import '@neuravision/construct/foundations.css';
@import '@neuravision/construct/components/components.css';
@import './generated/construct/tokens.css';
```

The compiler rejects invalid schemas, unknown paths, incomplete resolved shapes, bad references,
duplicate selectors, and failing contrast pairs. Hand-written CSS overrides remain possible as a local
escape hatch, but they bypass those contracts and should not be the source of a reusable product theme.

---

## Reduced Motion

Construct components use motion tokens and explicit `prefers-reduced-motion: reduce` paths. Do not add a
global `*` override: it can break necessary browser/application behavior. Disable or simplify each
component's non-essential transition at the owning layer.

---

## Contrast Compliance

The build verifies 53 standard pairs for every built-in and custom theme: text across common surfaces,
brand interaction states, focus rings, semantic states, avatars, charts, and button states. Thresholds
follow the applicable WCAG text or non-text requirement; this is a test contract, not a blanket product
certification.

Custom inputs can add product-specific pairs with `foreground`, `background`, and `minRatio`. Run
`npx construct-theme --theme ./product.theme.json --validate-only --report-contrast` in CI.
