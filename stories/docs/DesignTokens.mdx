# Design Tokens

Design tokens are the source of truth for reusable visual decisions in Construct. They encode colors, typography, spacing, radii, shadows, and motion into named values that stay consistent across components and themes, while component-local structural geometry remains with its owning stylesheet.

---

## Three-Layer Token Pipeline

Construct separates raw values, theme-aware intent, and stable component decisions. References flow primitive → semantic → component.

```
tokens/primitives.json
tokens/semantic.light.json
tokens/semantic.dark.json
tokens/semantic.high-contrast.json
tokens/components.json
        │
        ▼  schema + reference + contrast validation
tokens/tokens.css   ← CSS custom properties
tokens/tokens.json  ← Resolved JSON (for tooling)
tokens/tokens.js    ← JavaScript ESM exports
tokens/tokens.ts    ← Typed literal exports
```

> **Never hand-edit the generated files.** Edit the source JSON files and run `npm run build`.

### Layer 1 — Primitives

Raw design values that form the palette. They rarely change.

```json
{
  "color": {
    "orange": { "500": "#F4581C" },
    "stone": { "950": "#16130F" }
  },
  "space": { "4": 8, "6": 16 },
  "radius": { "md": 8, "lg": 12 }
}
```

### Layer 2 — Semantic

Contextual aliases that reference primitives by role. Swapping a theme means remapping semantic tokens — primitives stay untouched.

```json
{
  "color": {
    "brand": { "primary": "{color.stone.950}", "accent": "{color.orange.500}" },
    "text":  { "primary": "{color.stone.950}" }
  }
}
```

### Layer 3 — Component

Component decisions reference semantic or primitive intent. They provide stable customization points without moving component anatomy into the global semantic layer.

```json
{
  "button": {
    "height": "{size.controlHeight.md}",
    "radius": "{radius.control}"
  },
  "control": {
    "borderFocus": "{color.focus.ring}"
  }
}
```

Source contracts and custom-theme inputs are defined by the published JSON Schemas in `schemas/`.

## Typography Tokens

### Font Families

| CSS Variable | Value |
|-------------|-------|
| `--font-family-brand` | Lato (display & headings) |
| `--font-family-text` | Lato (body) |
| `--font-family-mono` | JetBrains Mono (code & data) |

Lato is a humanist sans-serif paired with JetBrains Mono for code and data. The aliases `--font-family-heading`, `--font-family-body`, and `--font-family-code` resolve to brand, text, and mono respectively. Foundations make no font request; use the optional `fonts.css` entry or self-host the documented weights.

## Using Tokens in CSS

```css
.my-card {
  background: var(--color-bg-surface);
  border: 1px solid var(--color-border-subtle);
  border-radius: var(--radius-card);
  box-shadow: var(--shadow-card);
  padding: var(--space-8);
}

.my-card__title {
  font-family: var(--font-family-heading);
  font-size: var(--font-size-2xl);
  color: var(--color-text-primary);
}
```

## Using Tokens in TypeScript

```ts
import { components, componentThemes, tokens, cssVars } from '@neuravision/construct/tokens';

// Resolved hex value
const brand = tokens.semantic.color.brand.primary; // '#16130F'

// CSS variable reference string (for inline styles)
const brandVar = cssVars.semantic.color.brand.primary; // 'var(--color-brand-primary)'

// Access theme-specific overrides
const darkBg = tokens.semanticThemes.dark.color.background.canvas;

// Component layer and its theme-resolved values
const buttonHeight = components.button.height;
const darkMetricBg = componentThemes.dark.metric.background;
const buttonHeightVar = cssVars.components.button.height;
```

## Building Tokens

After editing any source JSON file, regenerate the outputs:

```bash
npm run build
```

The build validates schemas, references, complete theme scopes, and contrast before writing. To verify all generated and package contracts in CI:

```bash
npm run check
```

Compile product themes with `npx construct-theme --theme ./brand.theme.json`. See the package Token Reference for the schema, partial override, and declared contrast contract.
